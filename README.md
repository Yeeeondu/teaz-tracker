- 매일 **00:05 KST**에 GitHub Actions가 자동으로 수집합니다. 늦어지거나 실패할 때를 대비해 03:05와 06:05에 다시 시도하며, 오늘 기록이 이미 있으면 건너뜁니다.
- 내 PC를 켜 둘 필요가 없고, 로그인도 필요 없습니다(공개 API `https://api.myteaz.io/chat/characters`만 읽음).
- 대시보드 주소: https://yeeeondu.github.io/teaz-tracker/

## 지금 바로 다시 수집하기

**Actions → 수집 및 배포 → Run workflow**를 누릅니다. **force**를 체크하면 오늘 기록을 지금 값으로 교체합니다. 순증은 수집 간격을 24시간으로 환산하므로 시각이 달라도 비교는 되지만, 몇 시간 간격으로 자주 교체하면 환산값이 크게 흔들릴 수 있습니다.

## 화면 구성

- **요약 카드**: 메시지 누적, 일 순증(24시간 환산)과 직전 7회 평균 대비 변화, 좋아요 누적, 캐릭터·원작 수
- **메시지 누적 / 좋아요 누적**: 선 = 누적, 아래 막대 = 일 순증
- **원작별 메시지**: 누적 / 일 순증 / 순증 점유율(그날 늘어난 메시지 중 각 원작의 비중) — 어느 원작이 대화를 끌고 있는지 확인
- **캐릭터별 카운터**: 날짜 선택, 캐릭터·원작 묶음 전환, 검색, 정렬, CSV 저장. 캐릭터 이름을 누르면 티즈 캐릭터 페이지로 이동

## 수집 방식과 해석

- **날짜**는 수집한 순간의 한국 날짜입니다. 0시 무렵에 수집하므로 "11/17" 값은 대체로 11/16 하루까지 쌓인 누적입니다(원본 사이트와 같은 기준).
- **일 순증** = (이번 값 − 직전 수집 값) × 24 ÷ 두 수집 사이 시간. GitHub 예약 실행이 1~수 시간 늦어져도 하루치로 비교되게 맞춘 값입니다. 마우스를 올리면 실제 증가량과 경과 시간도 보입니다.
- 새 캐릭터가 공개되면 그날 합계에 더해지고, 표에는 **신규**로 표시됩니다(개별 순증은 비교 기준이 없어 비움).
- 운영사가 카운터를 조정하면 순증이 음수로 나올 수 있습니다. 예: 11/14에 「애런 헌터」 카운터가 14,483 → 9,024로 줄어 합계 순증이 −1,471로 나왔습니다.
- 읽어 낸 캐릭터 수가 직전 기록의 60%에 못 미치면 사이트 장애로 보고 저장하지 않습니다.
- 공개 카운터는 매출이나 실제 이용자 수와 다릅니다.
- 공개 저장소에 60일 동안 활동이 없으면 GitHub가 예약을 끌 수 있지만, 매일 데이터가 저장되므로 보통은 문제가 없습니다.

## 커스터마이징 포인트

| 바꾸고 싶은 것 | 위치 |
|---|---|
| 수집 시각 | `.github/workflows/collect.yml`의 `cron` (UTC 기준, 한국시간에서 9시간을 뺌) |
| 장애 판단 기준 | `collector/collect.py`의 `MIN_RATIO` |
| 차트 색 | `site/style.css` 맨 위의 `--s1`~`--s7` |
| 카드·차트·표 구성 | `site/index.html`, `site/app.js` |

## 내 PC에서 실행해 보기

```bash
python collector/collect.py --force       # site/data/teaz.json 갱신
cd site && python -m http.server 8000     # http://localhost:8000 접속
```
